Le traitement sub-symbolique d'un LLM : pipeline de la tokenisation à la distribution de sortie

1 / 5 — Tokenisation

Étape 1 / 5 — Tokenisation

Le texte est découpé en sous-unités (tokens) par un algorithme BPE ou SentencePiece, puis chaque token est converti en un entier — son index dans le vocabulaire. Dès la première étape, toute sémantique est perdue : « traitement » et « traiter » peuvent avoir des IDs très éloignés. Le modèle ne lit pas des mots — il reçoit une séquence d'entiers. Type : INTEGER[ ]

Étape 2 / 5 — Embeddings

L'entier 14827 est mappé via la matrice d'embedding E ∈ ℝ^{V×d} — une ligne de cette matrice, V ≈ 100 000, d = 4 096. Résultat : 4 096 flottants sans signification intrinsèque. Ce qui encode les relations sémantiques, c'est la géométrie relative : « traiter » et « traitement » ont des vecteurs proches car ils co-occurent dans des contextes similaires pendant l'entraînement. Pas de symbole — de la géométrie statistique apprise. Type : ℝ^{4096}

Étape 3 / 5 — Matrices d'attention

Pour chaque token (la « requête »), l'attention projette les vecteurs sur 3 espaces : Q (query), K (key), V (value). Le produit QKᵀ mesure la similitude géométrique entre tokens dans ℝᵈ. Normalisé par softmax, ce score devient un poids de pondération des valeurs V. Aucune « compréhension » — une combinaison linéaire pondérée par des similarités statistiques. En parallèle, 32 à 128 « têtes » font ceci simultanément, chacune capturant un type de relation différent. Type : matmul ∈ ℝ^{d×d}

Étape 4 / 5 — N couches transformer

Le transformer empile N couches identiques. Chaque couche transforme les vecteurs via l'attention multi-têtes + un FFN (deux matrices + non-linéarité GELU) + connexions résiduelles + layer normalization. À aucun moment : pas de variable symbolique, pas de prédicat logique, pas de règle explicite. Des milliards de multiplications matricielles en cascade produisent des représentations de plus en plus abstraites — statistiquement corrélées avec des structures sémantiques, mais jamais symboliques. Type : cascade matmul ∈ ℝᵈ

Étape 5 / 5 — Distribution de sortie

La couche de sortie projette hₙ ∈ ℝᵈ sur un espace de logits de dimension V (~100 000 tokens) via W_lm, puis softmax normalise en probabilités. Le LLM n'a pas décidé de dire « données » — il a échantillonné selon une distribution. Le mot que vous lisez est l'artefact final d'une cascade sub-symbolique. C'est pourquoi la gouvernance de l'OC doit être externe : elle ne peut pas être injectée dans les paramètres du modèle — elle doit envelopper la sortie. Type : distribution sur ℝ^{V}
