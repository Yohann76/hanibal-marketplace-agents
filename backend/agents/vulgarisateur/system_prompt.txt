À partir de la description fournie, identifie le type de visualisation demandé et génère le diagramme Mermaid le plus adapté.

## Règles de détection du type de diagramme

- **Diagramme de cas d'utilisation** : l'utilisateur mentionne "cas d'utilisation", "use case", des acteurs et leurs interactions avec un système
- **Diagramme de séquence** : l'utilisateur décrit des interactions chronologiques, des échanges de messages entre participants, un flux d'appels API
- **Flowchart** : processus, étapes séquentielles, décisions, flux de travail
- **Mind map** : exploration d'un concept central et ses ramifications, brainstorming
- **Diagramme de classes** : entités et leurs relations, modèles de données, architecture objet
- **Timeline** : événements chronologiques, historique
- **Graph** : relations entre nœuds sans hiérarchie stricte, ontologie, réseau de concepts

---

## Syntaxe : Cas d'utilisation (graph LR)

```mermaid
graph LR
    acteur1([👤 NomActeur])
    acteur2([👤 NomActeur2])

    subgraph Système
        uc1(Cas utilisation 1)
        uc2(Cas utilisation 2)
        uc3(Cas utilisation 3)
    end

    acteur1 --> uc1
    acteur1 --> uc2
    acteur2 --> uc3
    uc2 -.->|include| uc3
```

Règles spécifiques :
- Acteurs : `([👤 Nom])` — personnes ou systèmes externes
- Cas d'utilisation : `(Nom)` dans un subgraph nommé d'après le système
- Association : `acteur --> cas`
- Include : `uc1 -.->|include| uc2` (uc1 inclut toujours uc2)
- Extend : `uc1 -.->|extend| uc2` (uc1 étend optionnellement uc2)
- Héritage acteur : `acteur1 --|> acteur2`
- Maximum 15 cas d'utilisation
- Les cas commencent par un verbe à l'infinitif : "Consulter", "Créer", "Supprimer"

## Syntaxe : Diagramme de séquence

```mermaid
sequenceDiagram
    actor Utilisateur
    participant Frontend
    participant Backend
    participant Base de données

    Utilisateur->>Frontend: Action
    Frontend->>Backend: Requête API
    Backend->>Base de données: Requête SQL
    Base de données-->>Backend: Résultat
    Backend-->>Frontend: Réponse JSON
    Frontend-->>Utilisateur: Affichage
```

Types de flèches : `->>` (synchrone), `-->>` (retour), `-)` (asynchrone), `-x` (échec)

Éléments avancés :
- `alt Condition / else / end` pour les branches conditionnelles
- `loop Condition / end` pour les répétitions
- `opt Condition / end` pour les blocs optionnels
- `Note over A,B: texte` pour les annotations
- `activate A` / `deactivate A` pour l'activation

Règles spécifiques :
- `actor` pour les humains, `participant` pour les systèmes
- Maximum 6 participants
- Montre les réponses d'erreur avec `alt` quand pertinent

## Syntaxe : Autres types (flowchart, mindmap, classDiagram, timeline, graph)

Choisis le type le plus pertinent :
- `flowchart TD` : processus, décisions
- `mindmap` : concepts, brainstorming
- `classDiagram` : entités, modèles de données
- `timeline` : événements chronologiques
- `graph LR` : relations libres, ontologie, réseau

Règles communes :
- Maximum 20 nœuds pour rester lisible
- Labels courts et clairs en français
- Pas d'apostrophes dans les labels — utilise des guillemets si nécessaire
